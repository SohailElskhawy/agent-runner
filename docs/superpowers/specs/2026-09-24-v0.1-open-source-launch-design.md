# V0.1 Open-Source Launch — Design Spec

**Date:** 2026-09-24
**Status:** Proposed — awaiting user review before implementation planning

## Context

Agentic Dev Runner is a local-first orchestration engine for reliable autonomous software development. The execution core (M1–M8 of `docs/ROADMAP.md`) is implemented and tested: 77 commits, ~865 test cases, 10 packages, SQLite persistence, crash recovery, Git worktree isolation, integration queue, workflow engine with bounded review loops, scheduler with parallel execution, and OpenCode + Codex adapters.

The goal is to finish fast and launch it as an open-source tool, usable by other developers and in the author's future projects.

**Remote:** `github.com/SohailElskhawy/agent-runner` (branch `master`, clean).

## Decisions taken during brainstorming

1. **Launch bar:** ship the proven execution core now; defer autonomous discovery/planning (M3) to v0.2.
2. **Distribution:** publish unscoped npm package `agentic-dev-runner` with bin `agentic`.
3. **Dogfood:** purpose-built 20-task scratch repo; deterministic fake agents in CI, one real-agent run documented locally.
4. **License:** MIT.
5. **Scope adjustment:** include `approve`, `retry`, `tasks` (list), and `doctor` CLI commands, plus four correctness fixes.

## Launch definition of done

A developer on a clean machine can `npx agentic-dev-runner@0.1.0 init`, author tasks, run them unattended in parallel with a real agent, recover from a crash, and inspect full history. CI is green on Windows, macOS, and Linux. README, LICENSE, and install guide exist. A 20-task roadmap completes under the runner with complete evidence and no unsafe overlap.

## W1 — Correctness fixes

### F1: Unify `agentic run <task-id>` onto the workflow pipeline

Today `run <task-id>` uses the legacy single-task orchestrator: no PLAN/REVIEW stages and **no integration verification** before DONE, diverging from the unattended path and violating ADR-008.

- Route single-task runs through the same workflow executor used by `run-all`.
- Required stages follow the task's workflow definition (`simple` = IMPLEMENT→VERIFY→INTEGRATE).
- Integration verification runs and is persisted (`integration.verification.completed`) before DONE on both paths.
- Scope validation applies to the actual Git delta on both paths.

**Acceptance:** a single-task run executes the resolved workflow stages; a new e2e test asserts the integration-verification event and DONE gating for `run <task-id>`; CLI parsing, exit codes, and output shape remain unchanged.

### F2: Windows `.cmd`/`.bat` agent shims must spawn

`packages/platform/src/processes/node-process-runner.ts:170` uses bare `spawn`, which cannot launch npm-installed agent shims on Windows (`opencode.cmd`, `codex.cmd`), blocking the cross-platform claim.

- Fix behind the platform abstraction: on Windows, invoke `.cmd`/`.bat` targets through `cmd.exe` with correct argument-array quoting (no shell-string construction for normal executables).
- Preserve stdout/stderr capture, exit codes, timeout, cancellation, and kill semantics.

**Acceptance:** a Windows fixture `.cmd` script runs through `ProcessRunner`; `agentic agents` detects an npm-installed shim; tests run on Windows CI and are listed in the release checklist.

### F3: Make human approval a real, bounded capability

`approval.required: true` is a permanent dead end: no approval state exists, so `selectRunnableTasks` returns `approval-required` forever.

- Add durable approval state to tasks (SQLite migration v10).
- Add `RunnerStore.approveTask` (transactional; rejects terminal/active states).
- Add `agentic approve <task-id>` (parse → app service → render; no orchestration in CLI).
- Persist an immutable `task.approval.granted` event; surface approval state in `status`/`inspect`.

**Acceptance:** an approval-required task is runnable after `approve` and not before; approving a DONE/running task fails safely; unit + CLI tests cover the lifecycle.

### F4: Reconcile `TASK_SCHEMA.md` with the validator

`TASK_SCHEMA.md` documents a `verification.<check>.required/reason` opt-out that `validateManualTaskInput` rejects (`rejectUnknownFields` on `VERIFICATION_KEYS`), and an oversized-task `SPLIT_REQUIRED` flow that does not exist.

- **Direction change from the brainstorming message:** align the doc to the implementation rather than the implementation to the doc. Waiving a check is already expressed by omitting it from `verification.required`; accepting the documented form would add syntax with no behavior. Rationale is recorded here for review.
- Update `TASK_SCHEMA.md`: remove the per-check opt-out example, mark oversized-task detection as v0.2.
- Add a test that every YAML example in `TASK_SCHEMA.md` that is in v0.1 scope parses cleanly through the ingestion validator.

**Acceptance:** schema doc and validator agree; parity test fails if they drift.

## W2 — CLI additions

All commands follow ADR-002: parse input → call application services → render. No orchestration in the CLI.

- **`agentic tasks`** — list tasks with id, title, status, priority, milestone, dependencies, attempt count, approval state, and ineligibility reason where applicable. Read-only.
- **`agentic retry <task-id>`** — allowed for `FAILED` and `NEEDS_HUMAN` tasks; transitions to `READY` and records `task.retry.requested`. Refuses `DONE`, active, and budget-exhausted tasks (attempt budget remains authoritative — release criterion 7). Refusal messages state the exact reason.
- **`agentic doctor`** — preflight checks: Node >= 24, git present, project initialized, state dir writable, `agentic.yaml` valid (or absent), agent probes, worktree dir writable. Exit 1 on FAIL, 0 with warnings otherwise.

**Acceptance:** each command has unit tests and at least one CLI-level test; `retry` honors attempt limits; `doctor` reports failures with actionable messages.

## W3 — Packaging & distribution

- Publish one public package: `agentic-dev-runner` (unscoped), bin `agentic`. Internal `@agentic-dev-runner/*` packages stay `private`.
- Bundle the CLI and all workspace dependencies into a single ESM bundle with esbuild (already present in the toolchain) targeting Node 24; builtins external.
- `files: ["dist"]`, `engines.node >= 24`, MIT license, repository/homepage metadata.
- Development workflow (`pnpm build/typecheck/lint/test`) stays unchanged; bundling is an added publish step.
- **Pack smoke test:** `pnpm pack` → install the tarball into a temp prefix → `agentic version`, `init`, `tasks add`, fake-agent `run`, `status`. Runs on all CI platforms.

**Alternatives rejected:** publishing all internal packages publicly (larger surface, version coordination); pnpm `bundledDependencies`/`deploy` (less predictable than an esbuild bundle).

**Acceptance:** tarball installs and runs on a clean temp dir on all three OSes; no workspace `*` dependencies leak into the published manifest.

## W4 — Release validation

- **V1 — CI matrix:** GitHub Actions, ubuntu/windows/macos × Node 24, pnpm 12.4.1 via corepack; lint, typecheck, build, test; real-agent tests stay env-gated.
- **V2 — 20-task DAG (criterion 1):** deterministic fake-agent fixture exercising dependency depth, parallel branches, disjoint and shared resources, and scope paths. Asserts all DONE, dependency order, no overlapping execution, integration order, and integration-verification events. Runs in CI with bounded runtime.
- **V3 — Forced-kill recovery (criterion 4):** spawns the built CLI, hard-kills the process tree (Windows `taskkill /T /F`; POSIX SIGKILL) at three interrupt points (agent execution, verification, integration), restarts, and asserts no duplicate commits/merges, no orphan claims/locks/queue entries, reconciliation events present, and safe convergence.
- **V4 — Provider failure (M084):** missing adapter → no attempt with structured reason; agent crash/timeout → `FAILED`/`BLOCKED` while independent tasks continue; queue and locks stay consistent.
- **V5 — Parallel stress (M083):** 8–12 tasks at `--parallel 4` including deliberate resource and path conflicts; invariant assertions (≤ max claims, ≤ 1 integrating, unique locks).
- **V6 — Cross-platform evidence (M079–M081):** CI green on all three platforms plus a manual smoke checklist in `docs/RELEASE.md`.
- **V7 — Real-agent dogfood (M085):** 20-task scratch repo executed with a real agent locally; transcript and artifacts in `docs/DOGFOOD.md`. Depends on the user's agent credentials.

**Acceptance:** V1–V6 automated and reproducible; V7 evidence committed.

## W6 — Release mechanics

- First publish is manual after the pack smoke passes; post-publish `npx` smoke in a temp dir.
- Tag-triggered publish workflow is deferred to v0.2.

## Constraints honored

- ADRs 001–018 unchanged; no architecture redesign.
- Platform-specific behavior stays behind platform abstractions; no shell strings.
- No new production dependencies anticipated; esbuild is a dev/build tool.
- Persistence accessed through `RunnerStore` only; schema changes via migrations.
- Small, independently reviewable changes; verification evidence required.
- Scope controlled: deferred items are explicit, nothing is silently dropped.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| F1 unification ripples through existing e2e expectations | Medium | Preserve `simple` workflow behavior first; update tests alongside |
| Windows `.cmd` quoting edge cases | Medium | Fixture-driven tests on Windows CI; no shell for non-shim executables |
| V2/V3 flakiness or CI runtime | Medium | Bounded fixtures, deadline polling instead of sleeps, pinned pnpm |
| npm name `agentic-dev-runner` unavailable | Low | Check first; fallback names prepared |
| Real-agent dogfood needs credentials | Certain | User performs V7 or provides access; CI covers deterministic variant |
| Scope creep during fixes | Medium | AGENTS.md scope rules; anything beyond W1–W6 goes to v0.2 |
