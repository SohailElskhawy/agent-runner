# Agentic Dev Runner — V0.1 Scope

## Goal

V0.1 proves that Agentic Dev Runner can reliably execute a bounded engineering roadmap using interchangeable coding agents.

The priority is reliability, not feature breadth.

## Required Capabilities

V0.1 must support:

- local Git repositories
- project documentation ingestion
- `AGENTS.md`
- readiness analysis
- bounded milestones
- small task generation
- dependency DAG
- durable local state
- crash recovery
- task attempts and retries
- at least two agent adapters
- deterministic agent routing
- fresh task context
- isolated Git worktrees
- plan and review stages
- implementation
- configurable verification
- controlled integration
- blocked-task handling
- progress/status reporting
- basic token, cost, and duration telemetry
- macOS, Linux, and Windows

## Initial Vertical Slice

Before building the full V0.1 feature set, implement:

```text id="7uwm4k"
manually defined task
→ persist task
→ create task worktree
→ construct ContextPack
→ invoke one coding agent
→ capture code changes
→ run verification
→ create atomic commit
→ integrate
→ persist DONE
```

This must work reliably before adding autonomous planning or parallel execution.

## V0.1 Execution Model

Normal tasks may use:

```text id="75c5a5"
PLAN
→ PLAN_REVIEW
→ IMPLEMENT
→ CODE_REVIEW
→ VERIFY
→ INTEGRATE
```

Workflow rigor may vary by task risk.

All retries and review loops must be bounded.

## Supported Execution Modes

V0.1 should support:

- `manual`
- `guarded`
- `autonomous`

Approval policies may remain simple initially.

## Routing

V0.1 routing is deterministic and rule-based.

Routing may consider:

- task complexity
- task risk
- required capability
- configured model class
- cost limits

V0.1 does not require learned or adaptive routing.

## Discovery

The system may help complete incomplete project context.

It may:

- identify missing information
- ask targeted questions
- propose defaults
- generate missing project documents

It must not silently invent important product or architectural decisions.

## Explicit Non-Goals

Do not build these for V0.1:

- graphical UI
- cloud control plane
- distributed workers
- team collaboration
- agent marketplace
- workflow marketplace
- Figma ingestion
- Jira integration
- Linear integration
- Slack/Discord/Telegram notifications
- GitHub PR automation
- automatic deployment
- remote execution
- learned model routing
- historical model benchmarking
- sophisticated ETA prediction
- automatic production infrastructure changes
- general-purpose AI product-design system

## Architectural Non-Goals

Do not introduce unless a demonstrated requirement appears:

- microservices
- Redis
- Kafka
- message brokers
- PostgreSQL
- Kubernetes
- Docker as a runtime requirement
- Electron
- arbitrary workflow plugins
- generic plugin framework

## Scope Control

Every implementation task must map to:

- an approved roadmap item
- a V0.1 requirement
- a discovered blocker
- a verification failure
- an approved task split

Do not create speculative features.

## Release Criteria

V0.1 is releasable when it can:

1. Run a real project with at least 20 tasks.
2. Execute at least two independent tasks concurrently.
3. Use at least two different coding-agent adapters.
4. Recover after forced process termination.
5. Prevent unsafe overlapping task execution.
6. Integrate isolated branches correctly.
7. Stop retries at configured limits.
8. Preserve complete attempt and event history.
9. Keep task contexts isolated and reproducible.
10. Prevent silent roadmap expansion.
11. Produce small inspectable commits.
12. Show reliable project status from the CLI.
13. Run on macOS, Linux, and Windows.

## V0.1 North Star

> Reliable unattended execution of a bounded engineering roadmap.

When forced to choose between more autonomy and more reliability, choose reliability.
